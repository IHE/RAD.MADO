# EU MADO call — 2026-08-20

## Web Viewer endpoint and the IHE IID connection type

**Decision:** The proposed change to the Web Viewer endpoint (`MadoWebViewerEndpoint`) to include the IHE IID (`ihe-iid`) connection type is **not appropriate** and will not be adopted.

**Rationale:**
- The Web Viewer endpoint's `address` is a fully populated URL that already contains all the information required to launch the viewer directly on the specific imaging study.
- The IHE IID content/connection type relates to a **base URL** to which invocation parameters must still be appended; it does not describe a fully-populated, study-specific launch URL.
- Because the two are semantically different (fully-populated study URL vs. base URL requiring parameter construction), folding `ihe-iid` into the Web Viewer endpoint would misrepresent how the address is meant to be used.

**Outcome:** Keep the Web Viewer endpoint using its dedicated `web-viewer` connection type with a fully-populated `address`. Do not add `ihe-iid` to this profile.
